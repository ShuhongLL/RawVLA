# RAW-LIBERO Benchmark Construction Protocol

## 1. Goal

This benchmark evaluates VLA robustness under **physically motivated illumination changes in the LIBERO simulator**, while keeping the RAW formation pipeline fixed.

The benchmark contains five illumination domains:

1. **ExtremeLow**
2. **Low**
3. **Normal**
4. **Over**
5. **ExtremeOver**

The intended causal chain is:

```text
LIBERO environment illumination
        ↓
8-bit rendered RGB
        ↓
fixed RGB→RAW unprocessing
        ↓
brightness-dependent RAW sensor noise
        ↓
simulated RAW observation
        ↓
VLA / ISP / proposed method
```

The benchmark is designed to answer:

> How robust is a VLA system to RAW observations produced under genuinely different simulated illumination conditions, rather than to an ISP-side brightness perturbation?

---

## 2. Important Scope and Assumptions

### 2.1 LIBERO provides 8-bit RGB, not physical sensor RAW

LIBERO renders an 8-bit RGB image. Therefore, this benchmark does **not** have access to true linear sensor measurements.

We instead construct a simulated RAW observation using a **fixed unprocessing pipeline**:

\[
I_{\mathrm{RGB8}}
\xrightarrow{\text{fixed unprocess}}
I_{\mathrm{RAW}}
\]

All unprocessing parameters must remain fixed across:

- tasks,
- illumination levels,
- episodes,
- methods,
- checkpoints.

The only environment-side variable in the main benchmark is illumination.

### 2.2 Illumination is changed in the simulator, not in the ISP

Low-light and over-bright conditions must be generated by changing the **LIBERO environment lighting** before rendering.

Do **not** simulate these conditions by multiplying, darkening, brightening, gamma-changing, or exposure-adjusting the already-rendered RGB/RAW image as the primary benchmark perturbation.

The intended intervention is:

\[
\text{Environment Lighting} \rightarrow \text{Rendered RGB} \rightarrow \text{Pseudo-RAW}.
\]

### 2.3 Limitation of overexposure simulation

Because LIBERO first produces 8-bit RGB, severe highlight clipping can already occur before RGB→RAW unprocessing.

Therefore, **Over** and **ExtremeOver** represent *simulated over-bright observations in the LIBERO rendering pipeline*, rather than a perfectly faithful physical RAW sensor with additional highlight headroom.

This limitation should be stated explicitly in the paper.

---

## 3. Benchmark Unit

Use all four standard LIBERO suites:

- LIBERO-Spatial
- LIBERO-Object
- LIBERO-Goal
- LIBERO-Long

Assuming 10 tasks per suite:

\[
40\ \text{tasks total}.
\]

For each task, evaluate **50 rollouts total**.

However, the 50 rollouts should **not** be 50 unrelated episodes randomly assigned to the five lighting domains.

Instead use:

\[
\boxed{10\ \text{base episode seeds} \times 5\ \text{lighting domains} = 50\ \text{rollouts/task}}
\]

This creates a paired benchmark.

---

## 4. Paired Episode Construction

For each task, first sample 10 base episode seeds:

```text
seed_01
seed_02
...
seed_10
```

Each base seed fixes all non-lighting environment variables, including as applicable:

- object initialization,
- robot initialization,
- task variation,
- language instruction,
- camera configuration,
- simulator randomness.

Then evaluate the **same base episode** under all five illumination domains:

```text
seed_01 + ExtremeLow
seed_01 + Low
seed_01 + Normal
seed_01 + Over
seed_01 + ExtremeOver

seed_02 + ExtremeLow
seed_02 + Low
...
```

Therefore, each task has:

| Lighting domain | Episodes/task |
|---|---:|
| ExtremeLow | 10 |
| Low | 10 |
| Normal | 10 |
| Over | 10 |
| ExtremeOver | 10 |
| **Total** | **50** |

This pairing is preferred because lighting-condition comparisons are not confounded by different object/robot initializations.

---

## 5. Lighting Domains

Each lighting domain should be a **range**, not a single fixed illumination value.

For lighting domain \(d\):

\[
L \sim p(L\mid d).
\]

For each `(task, base_seed, lighting_domain)` tuple, sample one illumination value once using a fixed benchmark seed.

The sampled value is then frozen in the benchmark manifest.

### 5.1 Suggested parameterization

Define illumination relative to LIBERO's nominal lighting using an EV-like variable:

\[
L = L_0 2^{\Delta EV},
\]

where \(L_0\) is the nominal Normal illumination.

An **initial calibration proposal** is:

| Domain | Candidate relative range | Intended appearance |
|---|---:|---|
| ExtremeLow | \([-4.5,-3.0]\) EV | signal close to the noise floor; severe visibility loss |
| Low | \([-3.0,-1.5]\) EV | clearly under-illuminated but still visually recoverable |
| Normal | \([-0.5,+0.5]\) EV | close to standard LIBERO illumination |
| Over | \([+1.5,+3.0]\) EV | strong highlights / partial clipping |
| ExtremeOver | \([+3.0,+4.5]\) EV | extensive clipping / severe information loss |

**These ranges are placeholders and must be calibrated empirically.**

The final ranges should be selected based on rendered-image / simulated-RAW statistics rather than EV labels alone.

### 5.2 LIBERO v1 implemented ranges and light rig

The released `rawvla-bench-light-libero-v1` manifests use the calibrated ranges
below. Each `(suite, task_id, base_seed, lighting_domain)` samples one EV value
from the domain range with the fixed benchmark seed and stores the sampled EV,
`lighting_scale = 2 ** lighting_ev`, `agentview_table_flood`, and RAW
full-well pressure in the manifest.

| Domain | Implemented EV range | Rig | Agentview table flood | RAW saturation EV |
|---|---:|---|---:|---:|
| ExtremeLow | \([-5.5,-4.0]\) EV | `common_agentview_key` | `0.0` | `0.0` |
| Low | \([-4.0,-2.5]\) EV | `common_agentview_key` | `0.0` | `0.0` |
| Normal | \([-0.5,+0.5]\) EV | `common_agentview_key` | `0.0` | `0.0` |
| Over | \([+1.5,+3.0]\) EV | `common_agentview_key` | \([0.00,1.00]\) | \([0.50,1.00]\) |
| ExtremeOver | \([+6.0,+8.0]\) EV | `common_agentview_key` | \([1.00,2.00]\) | \([1.00,1.50]\) |

For domains with flood and RAW-saturation ranges, the same uniform sample `u`
is used for the domain EV, flood, and saturation interpolation. Within one
domain, higher EV samples therefore also receive stronger table flood and
stronger full-well pressure.

The `common_agentview_key` rig is implemented as real MuJoCo XML light slots.
For each LIBERO episode, RAWVLA-Bench first performs the normal reset with the
manifest seed and then derives a RAW XML by injecting those slots into the
current compiled scene XML. RAW episodes reset from that episode-specific RAW
XML; RGB baseline episodes keep the original reset scene. Runtime domain
changes only update light arrays:

```text
original LIBERO lights = captured_original_lights * lighting_scale
headlight = captured_original_headlight * lighting_scale
rawvla_agentview_key = 0.02 * lighting_scale
rawvla_agentview_flood_* = agentview_table_flood
```

Do not multiply `agentview_table_flood` by `lighting_scale` again. It is valid
to reset a RAW episode from the episode-specific RAW XML before
`set_init_state`; it is not valid for per-domain lighting application to
generate or switch XML.

## 6. Calibration of the Five Domains

Before freezing the benchmark, run a calibration sweep over representative tasks/scenes.

For candidate illumination values, record at least:

- mean / median luminance,
- dark-pixel ratio,
- highlight-clipping ratio,
- pseudo-RAW mean signal,
- pseudo-RAW saturation ratio,
- estimated SNR,
- representative visual examples.

The five domains should satisfy the following qualitative targets.

### ExtremeLow

- large fraction of the signal near the black/noise floor;
- strong visibility loss;
- low SNR after RAW noise simulation;
- task should not be universally impossible.

### Low

- clearly lower signal than Normal;
- moderate-to-strong noise after RAW noise simulation;
- objects/task semantics mostly remain recoverable.

### Normal

- matches the standard LIBERO appearance as closely as possible;
- serves as the reference domain.

### Over

- noticeable bright-region clipping;
- scene remains partly recoverable.

### ExtremeOver

- substantial saturation / clipping;
- severe but not necessarily universally impossible.

Avoid choosing ranges that make one domain trivially 0% or 100% successful for nearly every model.

---

## 7. Sampling Within Each Lighting Range

For each base seed \(s\) and domain \(d\), sample one lighting value:

\[
\Delta EV_{s,d} \sim U(a_d,b_d),
\]

or another explicitly defined fixed distribution.

Example:

```text
Task: Spatial-01
Base seed: 03

ExtremeLow:  -3.84 EV
Low:         -2.21 EV
Normal:      +0.17 EV
Over:        +2.42 EV
ExtremeOver: +3.77 EV
```

The illumination value must:

1. remain constant throughout the rollout;
2. be sampled only once when constructing the benchmark;
3. be stored in the benchmark manifest;
4. be identical for every evaluated method.

Do not resample illumination every time a model is evaluated.

---

## 8. Fixed RGB→RAW Unprocessing

All rendered 8-bit RGB images are converted using the same fixed unprocessing configuration.

Conceptually:

\[
I_{\mathrm{RAW}} = U(I_{\mathrm{RGB8}};\theta_U),
\]

where \(\theta_U\) is fixed for the entire benchmark.

The fixed configuration should include all relevant choices such as:

- inverse tone mapping,
- inverse gamma,
- inverse color correction,
- white-balance gains,
- Bayer pattern,
- black level,
- bit-depth normalization,
- clipping rule.

No condition-specific ISP parameter tuning is allowed during benchmark construction.

This is essential because the benchmark is intended to vary **environment illumination**, not ISP behavior.

---

## 9. Brightness-Dependent RAW Noise

Low-light observations should include physically motivated RAW noise after unprocessing.

A recommended simple model is signal-dependent shot/read noise:

\[
\operatorname{Var}(n\mid x)=a x+b,
\]

where:

- \(x\) is the pseudo-RAW signal,
- \(a\) controls signal-dependent shot noise,
- \(b\) controls signal-independent read noise.

Then:

\[
\tilde{x}=\operatorname{clip}(x+n).
\]

### Recommended benchmark policy

Use **one fixed sensor-noise model** across all illumination domains.

The underlying sensor parameters \((a,b)\) remain fixed, while the input signal \(x\) changes because the environment illumination changes.

This naturally creates lower effective SNR in darker scenes:

- under low illumination, the signal decreases;
- read noise becomes relatively more important;
- relative noise becomes stronger;
- ExtremeLow becomes noisier than Low without manually assigning an arbitrary Gaussian noise level to each category.

If the implementation requires an explicit brightness-conditioned noise function, define it deterministically from the pseudo-RAW signal or measured brightness, not from the categorical label alone.

### Noise random seed

Noise must also be reproducible.

For every `(task, base_seed, lighting_domain)` entry, store a fixed noise seed.

A convenient deterministic convention is:

```text
noise_seed = hash(task_id, base_seed, lighting_domain)
```

If frame-level stochastic noise is used, derive frame noise deterministically from:

```text
(task_id, base_seed, lighting_domain, frame_index)
```

All methods must therefore experience the same stochastic benchmark process.

---

## 10. What Is Randomized and What Is Fixed

### Randomized once during benchmark construction

- base episode seed,
- illumination value within each lighting-domain range,
- sensor-noise seed.

### Fixed after benchmark release

- task list,
- 10 base seeds/task,
- five illumination values associated with every base seed,
- all simulator initialization values,
- fixed unprocessing parameters,
- RAW noise model,
- RAW noise seeds,
- evaluation horizon and success criteria.

### Not randomized in Benchmark v1

To isolate illumination robustness, do **not** simultaneously randomize:

- camera pose,
- camera intrinsics/FOV,
- light direction,
- light color / color temperature,
- background,
- object appearance,
- ISP parameters.

These can be introduced later as separate extensions.

---

## 11. Benchmark Size

For each model:

\[
40\ \text{tasks}
\times 10\ \text{base seeds/task}
\times 5\ \text{lighting domains}
= 2000\ \text{rollouts/model}.
\]

Equivalently:

\[
40\ \text{tasks} \times 50\ \text{rollouts/task}=2000.
\]

Each lighting domain contains:

\[
40 \times 10 = 400\ \text{rollouts/model}.
\]

Each LIBERO suite contains, per lighting domain:

\[
10\ \text{tasks} \times 10\ \text{episodes}=100\ \text{rollouts/model}.
\]

This gives substantially more stable suite-level estimates than the 10 rollouts available for an individual task-condition pair.

---

## 12. Evaluation Metrics

### 12.1 Primary metric: Success Rate

For each lighting domain \(d\):

\[
SR_d = \frac{1}{N_d}\sum_i \mathbf{1}[\text{episode}_i\ \text{succeeds}].
\]

Report separately for:

- ExtremeLow,
- Low,
- Normal,
- Over,
- ExtremeOver.

### 12.2 Suite-level reporting

For each method, report:

| Method | ExtremeLow | Low | Normal | Over | ExtremeOver |
|---|---:|---:|---:|---:|---:|
| Method A |  |  |  |  |  |
| Method B |  |  |  |  |  |

for each of:

- LIBERO-Spatial,
- LIBERO-Object,
- LIBERO-Goal,
- LIBERO-Long,
- Overall.

### 12.3 Robustness drops

Use Normal as the reference:

\[
\Delta SR_d = SR_d - SR_{Normal}.
\]

Important robustness summaries include:

\[
SR_{LowLight}=\frac{SR_{Low}+SR_{ExtremeLow}}{2},
\]

\[
SR_{OverExposure}=\frac{SR_{Over}+SR_{ExtremeOver}}{2}.
\]

A challenging-condition average can additionally be reported:

\[
SR_{Challenging}
=
\frac{SR_{ExtremeLow}+SR_{Low}+SR_{Over}+SR_{ExtremeOver}}{4}.
\]

Do not use a five-condition average as the only headline metric, because equal weighting implicitly assumes that all five environments are equally likely in deployment.

---

## 13. Paired Robustness Analysis

Because every base episode is evaluated under all five illumination domains, condition-level robustness can be analyzed per episode.

For base episode \(s\):

```text
Normal(s)      → success / failure
Low(s)         → success / failure
ExtremeLow(s)  → success / failure
Over(s)        → success / failure
ExtremeOver(s) → success / failure
```

This permits analysis such as:

- Normal-success → Low-failure transition rate;
- Normal-success → ExtremeLow-failure transition rate;
- Normal-success → Over-failure transition rate;
- condition-specific paired bootstrap confidence intervals.

This is preferable to comparing lighting conditions constructed from unrelated episode seeds.

Release a manifest containing at least:

```yaml

lighting_value: -2.21
lighting_unit: relative_ev
noise_seed: 184233
unprocess_config: raw_v1
noise_config: sensor_noise_v1
```

The complete benchmark should be reproducible from the manifest and simulator version.

Suggested unique identifier:

```text
{task_id}_{base_seed}_{lighting_domain}
```

Example:

```text
libero_spatial_01_seed03_low
```

---

## 15. Required Sanity Checks Before Freezing the Benchmark

Before evaluating VLA baselines, verify:

1. **Normal consistency**
   Normal should closely reproduce standard LIBERO observations before unprocessing.

2. **Monotonic brightness trend**
   Image/RAW brightness statistics should decrease from Normal → Low → ExtremeLow and increase from Normal → Over → ExtremeOver.

3. **Monotonic low-light SNR trend**
   Estimated effective SNR should worsen from Normal → Low → ExtremeLow.

4. **Monotonic saturation trend**
   Saturated-pixel fraction should increase from Normal → Over → ExtremeOver.

5. **No universal impossibility**
   ExtremeLow and ExtremeOver should be challenging but should not make almost every task deterministically impossible.

6. **Seed reproducibility**
   Re-running the same manifest entry must regenerate the same initial scene, illumination, and RAW-noise process.

7. **Method fairness**
   Every baseline and proposed method must use exactly the same benchmark manifest.

---

## 16. Recommended Final Benchmark Definition

The recommended RAW-LIBERO v1 benchmark is:

\[
\boxed{
40\ \text{LIBERO tasks}
\times
10\ \text{paired base seeds}
\times
5\ \text{lighting domains}
}
\]

for a total of:

\[
\boxed{2000\ \text{rollouts per model}}.
\]

Each lighting domain is defined as a calibrated illumination **range**.

For every base episode:

1. keep all non-lighting simulator variables fixed;
2. sample one lighting value from each of the five domain ranges using fixed seeds;
3. render LIBERO's 8-bit RGB under that environment illumination;
4. convert RGB to pseudo-RAW using one fixed unprocessing pipeline;
5. apply one fixed signal-dependent RAW noise model with reproducible noise seeds;
6. evaluate all methods on the exact same frozen benchmark manifest.

In short:

> **Range-defined lighting domains, paired episode seeds, fixed sampled illumination values, fixed unprocessing, and brightness-dependent reproducible RAW noise.**

This should be the main benchmark protocol. Fixed single-point illumination sweeps can be used separately for controlled analysis/ablation, but not as the primary benchmark.
